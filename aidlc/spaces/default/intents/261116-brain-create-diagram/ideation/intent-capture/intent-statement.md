# Intent Statement — 讓大腦直接建立新的架構圖

## Problem Statement

使用者在入口頁或小助手說「幫我畫一張……架構圖」時，大腦應在目前的作業對象（系統）下新建一張圖並交給架構設計能力產出，而不是要求使用者先到工作區建立空白圖。[desc]

這件事要解決兩個問題：一是使用者說要畫圖、系統下卻沒有圖時流程直接斷掉，必須離開對話去工作區建空白圖再回來；二是使用者不知道要先建圖，以為大腦壞了。[Q1]

## Target Customer

所有有大腦使用權（K1）的使用者。[Q2]

K1 是「使用大腦」的權限，與可以建立、修改架構圖的「架構編輯權」是分開的兩種權限；有 K1 但沒有架構編輯權的人也會說要畫圖，他們得到的回應見下表。[Q9]

## Success Metrics

在入口頁或小助手說一句「幫我畫一張……架構圖」，不必離開對話，就在目前系統下得到一張完成的新圖，且專案頁看得到它。[Q6]

## Initiative Trigger

觸發點是上述流程斷掉的狀況：系統下沒有圖時，使用者無法在對話中直接請大腦畫圖。[Q1]

## 產品行為的已定邊界

| 情況 | 已定行為 | 來源 |
|---|---|---|
| 作業對象已有圖，使用者說「幫我畫一張……架構圖」 | 依句意判斷：說「新的／另一張」就新建，說「改／加上」就改目前的圖；判斷不出來就反問 | [Q3] |
| 說要畫圖，但沒有選作業對象，或作業對象只是專案、沒有系統 | 反問要掛在哪個系統，列出使用者擁有的系統讓他選 | [Q4] |
| 新圖的名稱 | 由大腦依使用者的句子自動取一個簡短名稱 | [Q5] |
| 有 K1、但沒有架構編輯權的人說要畫圖 | 不新建，明確回覆「建立架構圖需要架構編輯權」並說明可向誰申請 | [Q9] |
| 系統下有多張圖，使用者說「改一下那張圖」 | 作業對象已選到某張圖就改那張；只選到系統時，反問要改哪一張並列出系統下的圖 | [Q10] |
| 使用者名下沒有任何系統時說要畫圖 | 回覆需要先建立專案與系統，並提供到專案頁的路徑 | [Q11] |

## Initial Scope Signal

- **workflow-selected**：`bugfix`。[scope]
- **使用者確認的產品邊界**：第一版沒有特別要排除的項目。[Q8]
