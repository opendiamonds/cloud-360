## Tradeoffs
<!-- example: 2026-05-29T10:14:32Z — picked TDD over BDD this run; the team is unit-first and the domain is well-understood -->
- 2026-09-27T14:09:23Z — **`ollama/ollama:latest` 沒釘版本，而我選擇「記下來並就地註明」而不是挑一個版本號。** 同一輪改動的另兩個 image 都釘了主版本，這一個沒有——這是本輪**新引入**的不一致（不是繼承既有的依賴未 pin 問題）。deploy-on-merge 之下任何重新部署都可能靜默換掉 Ollama runtime，而 compose 改動沒有任何 CI 閘門看得到。不逕自釘版本的理由：挑版本要先確認與 `bge-m3`（dense 1024）的相容性，**憑猜寫一個數字比不釘更糟**——那會讓下一個人以為這個版本被驗證過。已記為 `OPEN-10` 並在 compose 就地註明。
- 2026-09-27T14:46:07Z — **R-02 的修法選「新增部署期反向探測」而不是「補測試」，因為那個失敗模式在測試層碰不到。** 「`redis-server` 對重複 `--user` 去重」只會在真實 redis 啟動時發生，單元測試層沒有受測對象；而它的後果是 `default` 保留全權、容器正常啟動、healthcheck 綠燈——**無聲的權限過寬**。所以正確落點是部署期斷言（以 `default` 執行 `SET` 應回 `NOPERM`），形狀與本輪已加的資料面探測完全相同、成本極低。這也回答了為什麼上一版的 `OPEN-2` 寫「失敗會大聲」是錯的：對這一種失敗模式它不成立。
