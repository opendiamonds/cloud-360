## 三、問題

### WO1. 「產生自然語言回覆」由誰負責？（承接 `OQ-N1`／`J-13`）

`contract-summary.md:1431` 查出：沒有任何單元擁有「產生大腦的自然語言回覆」。`BrainGateway`
只轉送、`IntentRouter` 只分類、`WorkOrchestrator` 只編排；但 `[RA:FR8.1]` 要求回覆逐步顯示。

A) **編排層用固定模板產生狀態訊息，能力本身的文字照轉**（建議）：工作項建立、等待、完成、
   失敗、停掉時，各送一則固定句型的訊息；A1 回傳的說明文字逐段轉送（它本身就是 SSE）；
   成本完成時送結構化卡片。不新增任何 LLM 呼叫、不新增依賴邊、不增加費用。代價：沒有
   「大腦用自己的話總結」這一層。
B) **`U12` 另呼叫 LLM 產生總結回覆**：體驗較像對話，但每回合多一次 LLM 費用，且需要
   `U11 → U12` 的新依賴邊（要送回 delivery-planning），也會出現第四個 OpenRouter 客戶端。
C) **由 `U13 brain-gateway` 產生**：同樣多一次 LLM 呼叫，且 `U13` 要新增對 LLM 介面的依賴。

### WO2. 什麼情況下工作項是「等待中」？（承接 `H-3`／`J-3`）

`AC5.1.2` 要求「第二項依賴第一項的結果時，狀態是等待中且說明在等什麼」，但上游沒定義
「依賴」。

A) **同一句話裡，成本或檢視類排在架構設計之後時，等架構設計完成**（建議）：因為成本與
   檢視要看改過的圖；其他組合（例如成本＋檢視）各自同時進行。規則簡單、可測，涵蓋
   `AC5.1.1` 的例句「改架構圖加 Redis 快取，然後估一下成本差額」。
B) **同一句話的多個意圖一律依序執行**：每一項都等前一項。最簡單，但兩件不相干的事也要排隊。
C) **一律同時進行**：「等待中」不會出現，`AC5.1.2` 無法滿足。不建議。

### WO3. 工作項存在哪裡？

`K-11` 寫「隨 session key 存放於 Redis，TTL 到期一起消失」，但已交付的 `U10 SessionStore`
沒有工作項的讀寫方法。

A) **擴充 `U10` 的 SessionStore，加上工作項讀寫方法，與 session 共用同一個 Redis key 與到期時間**
   （建議）：到期一致、原子；代價是改動已交付的 `U10` 程式（跨單元修改，同 `U15` 改 `U8` 的先例）。
B) **`U12` 自己的 Redis key，寫入時對齊 session 剩餘到期時間**：不改 `U10`，但兩個 key 可能
   不同步——session 已過期而工作項還在，或反過來。

### WO4. 使用者說「不是這個」之後，怎麼改交給正確的功能？

`AC1.3.3` 要求「改交給正確的功能，新工作項與被停掉的那項同時可見」，但 `K-11` 的
`correct(principal, session_key, work_item_id)` 沒有「改交給誰」的參數，而路由層只回最佳的一個判讀。

A) **只停掉該項，請使用者再說一次要做什麼，下一句重新判讀後建立新工作項**（建議）：不改
   `U11`、不新增畫面元件；被停掉的那項保留在清單上，新的一項出現後兩者同時可見。
B) **停掉後自動改交給原判讀的第二名**：需要改 `U11` 回傳排名，且第二名不一定是使用者要的。
C) **停掉後列出其他能力讓使用者點選**：需要 `U14` 新增選擇畫面。

### WO5. 問成本時，用哪一份估價表？

既有 C1 的估價表掛在架構圖下（`estimate_sets.diagram_id`），一個系統可能有多張圖、多份估價表；
成本建議的工作在上傳時就已啟動，大腦只需讀取它的狀態事件。

A) **取目標系統下、使用者看得到的最新一份估價表；沒有就讓工作項失敗，說明「此系統尚無估價表」
   並附成本頁連結**（建議）：一句話就能得到答案；`estimateSetId` 由此填入。
B) **有多份時列出讓使用者選**：較精確，但多一次來回，且需要 `U14` 的選擇畫面。

### WO6. 架構設計的結果怎麼讓架構圖頁看得到？（`AC1.1.4`）

既有 A1 的 `POST /api/architecture/generate` 只回傳產生的圖（SSE），**不存檔**；存檔是另一個端點
`PUT /api/collab/diagrams/{diagram_id}`。

A) **`U12` 先讀目標架構圖現有內容交給 A1，再經既有的存檔端點（帶使用者 token）存回，並寫一列
   變更紀錄**（建議）：架構圖頁直接看到新圖。目標圖的決定：脈絡列已選定圖就用它；只選到系統時，
   該系統恰有一張圖就用它，否則工作項失敗並請使用者在脈絡列選定圖。
B) **結果只存在大腦工作階段，由架構圖頁讀取**：不碰既有存檔流程，但要改 `/workspace` 頁去讀
   大腦的工作階段，屬另一個單元的範圍。
