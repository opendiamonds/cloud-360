## 〇、本單元的效能面

本單元零新進程、零新監聽埠（`unit-of-work.md:48`，embedded）。它對延遲的唯一真實影響是：**交辦之後多快讓使用者
看到回覆**，以及**背景執行對其他請求造成多少負擔**。能力本身（A1 產圖、A3 檢視、C1 建議）的耗時屬既有能力，
不在本單元控制內。

## 一、先回覆、後執行（承接 `NFR3`）

| id | 需求 | 二元判準 |
|---|---|---|
| **`NFR12.1`** | `dispatch` 在送出建立／等待訊息並回傳之前，**不等待任何**對既有能力的呼叫（`BR58.2`）。`NFR3` 的 2 秒預算幾乎全歸路由層（`U11`），本單元不得再吃掉它 | 以永不返回的能力替身執行 `dispatch`：`dispatch` 在 1 秒內回傳，且 sink 已收到本輪的建立訊息 |
| **`NFR12.2`** | 同步阻塞的 facade 呼叫（`MemoryFacade.write`、`HierarchyFacade.*`）一律以 `asyncio.to_thread` 執行，不在事件迴圈上直呼（`BR51.5`／`BR51.7`） | 測試替身記錄呼叫所在的執行緒：與事件迴圈執行緒不同 |

## 二、背景負擔

| id | 需求 | 二元判準 |
|---|---|---|
| **`NFR12.3`** | 成本輪詢間隔 2 秒，單一成本工作項的快照讀取次數有上界：牆鐘上限 360 秒內至多 180 次（`BR57.1`／`BR56.6`） | 假時鐘推進 360 秒：替身被呼叫次數 ≤ 180，之後工作項為失敗「成本分析逾時」 |
| **`NFR12.4`** | 估價表搜尋找到第一份符合者即停止翻頁（`BR56.3`），不讀完全部頁 | 替身提供 3 頁、符合者在第 1 頁：只讀 1 頁 |
| **`NFR12.5`** | 編排層不呼叫任何 LLM（`[WO1]`=A；承接 `NFR9` 的「盡量省」原則） | 本單元新增模組對 `llm_provider`、`openai`、`langchain`、`langgraph` 的 import 數為 0（grep） |

## 三、刻意不設的目標（附理由，不留空白）

| 不設 | 理由 |
|---|---|
| 絕對延遲數字（如 dispatch p95 ≤ N ms） | 本 repo 沒有延遲量測機制（`U19`／`U20` 同站已查證）；`NFR3` 的量測落點是 `build-and-test`。以 `NFR12.1` 的「不等待能力」代替——它是 `NFR3` 不被本單元破壞的必要條件 |
| 能力執行時間 | A1／A3／C1 的耗時屬既有能力；本單元只以牆鐘上限（`BR56.6`）給它上界 |
| 吞吐量 | 交辦來源是人在入口頁說一句話，頻率遠低於任何既有端點；無上游流量數據 |
