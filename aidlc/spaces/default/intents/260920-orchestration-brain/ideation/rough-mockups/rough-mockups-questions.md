## R12. 需求欄位是固定 schema 還是可擴充

會議結論舉例「SLA、TPS、使用客群」，但沒說這是全部還是舉例。這決定線框畫的是
固定表單還是可增欄的表格。

- **A**：**固定欄位集合**，本輪由設計階段定出一份清單，agent 只能讀寫清單內的欄位。
- **B**：**可擴充的鍵值對**，agent 可新增未預期的欄位名。
- **C**：**固定骨幹 ＋ 自由備註區**——常用欄位固定，其餘進一個自由文字區。
- **D**：**按 agent 分組的固定欄位**——成本 agent 一組、架構 agent 一組，各組欄位固定但可隨新 agent 增組。

[Answer]: D — 按 agent 分組的固定欄位（組內固定，可隨新 agent 增組）

**作答後果**：需求籤的線框畫成**分組表單**而非自由表格——成本 agent 一組（SLA、TPS、
使用客群…）、架構 agent 一組，組內欄位固定且可型別化、可驗證。與會議結論逐字的
「彙整所有其他功能性 agent 的所需要的需求」對應。**刻意不選自由鍵值對或自由備註區**：
那會把欄位語意交給 LLM 解析，而 `project.md` 記載本 repo 的三塊結構性盲區之一正是
「所有 LLM 路徑」。代價是新 agent 上線要同步加一組定義。
