# Reliability Requirements — U4 `security-reviewer-permission`

> Stage: nfr-requirements（Construction 3.2）· Unit: `security-reviewer-permission`（kind: service）
> 上游來源：`../functional-design/business-logic-model.md`、`business-rules.md`、`domain-entities.md`、`../../../inception/requirements-analysis/requirements.md`（下稱 requirements）、`../../../inception/application-design/components.md` C-7、`component-methods.md`、`decisions.md`、`services.md`。
> 問答定案：Q1=A（high-risk 條款適用）、Q2=A（rollback 為管理員經介面撤銷）。

## 本單元的可靠性核心：它的失敗是靜默的

本單元存在的理由，就是因為「改了預設值但既有環境沒生效」這件事**會靜默發生且 CI 全綠**。因此它自己的失敗**更不能**是靜默的。

## R-1 四態記錄為強制需求

| 狀態 | 等級 | 需求 |
|---|---|---|
| 已套用 | 正常 | 記錄本次確實更新了一列 |
| 已跳過（無需動作） | 正常 | 值已正確，或最後異動者已是補丁標記 |
| **未套用：該列已被管理員異動** | **需人工處置** | 必須帶出該欄的**實際值**供判讀，並觸發部署後的人工核對 |
| **未命中目標列** | **需人工處置** | 角色或功能識別碼可能被改過 |

**後兩態必須在啟動日誌上明顯可見**，且**不得**與前兩態混為同一則訊息。這是 3.1 承接上游 M1-a 的直接結果 —— 上游把「已套用過」與「已被管理員調整」合為一格，而死角恰好落在後者。

## R-2 寫入不得被靜默丟棄

| 面向 | 需求 |
|---|---|
| **需求** | 更新必須**自行提交**，且提交失敗必須以錯誤級記錄 |
| **為何是可靠性需求而非實作細節** | 啟動流程的初始化區塊包在一個會復原且**不重新拋出**的例外處理中；若沿用其工作階段而未自行提交，變更會在區塊結束時被無聲丟棄，而日誌可能仍顯示「已套用」 |
| **機制** | 3.1 Q2=A 定案：位於該區塊之後、使用自行提交的連線 |

**這一條與 R-1 是一組**：R-1 保證結果可觀察，R-2 保證觀察到的結果為真。缺任一項，另一項都會變成誤導。

## R-3 冪等：重複啟動不改變結果

| 面向 | 需求 |
|---|---|
| **需求** | 連續多次啟動的最終狀態相同，且**不得**累積副作用 |
| **機制** | 條件式謂詞 + 值已正確就不寫（3.1 的 R2／R3） |
| **具體保證** | 不會反覆推進最後異動時間；不會把種子寫的列誤標為補丁改的 |

## R-4 失敗不得阻斷服務啟動

| 面向 | 需求 |
|---|---|
| **需求** | 本單元的任何失敗**不得**使服務啟動失敗 |
| **理由** | 一個權限列沒套用成功，其後果是「一個角色進不了一個頁面」；讓整個服務起不來的後果嚴重得多，且會使 R-1 的日誌根本無人看得到 |
| **配套** | 失敗必須以錯誤級記錄（含例外型別），且落在需人工處置的等級 |

## 本單元無法保證的事（如實記載）

| 事項 | 為何 |
|---|---|
| 既有環境的套用**有自動化驗證** | **沒有**。3.1 已如實記載：測試輔助模組直接由模型建表、從不呼叫啟動流程，把本單元整個刪掉現有測試照樣通過 |
| R2 死角的**自動偵測** | 只能靠 R-1 的第三態告警 + 部署後人工核對。在該路徑上，「不依賴人工步驟即自動生效」的承諾**不成立** |
| 權限變更的**長期稽核軌跡** | 保存期約等於兩次部署間隔（requirements C-7 的既有約束） |
