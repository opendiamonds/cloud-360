> 問答定案：Q1=A（high-risk 條款適用）、Q2=A（rollback 為管理員經介面撤銷）。

## 本單元的擴展性結論：成本為常數，不隨任何維度成長

## S-1 成本與所有規模維度無關

| 維度 | 本單元的成本變化 |
|---|---|
| 帳號數 | **不變** —— 只動一列，與帳號數無關 |
| 請求量 | **不變** —— 不在請求路徑上 |
| 角色數 | **不變** —— 只動目標角色那一列 |
| 權限矩陣列數 | **不變** —— 單列主鍵定位，不掃全表 |
| 部署副本數 | **每副本一次**（見 S-2） |

**需求**：本單元的成本必須維持為**常數**。任何會使它隨上述維度成長的實作（例如掃描全表尋找目標列）皆不符本需求。

## S-2 多副本下必須維持冪等

| 面向 | 需求 |
|---|---|
| **需求** | 多個副本同時啟動並執行本單元時，結果必須一致且無錯誤 |
| **機制** | 目標式更新為單列覆寫，且值相同（皆為開啟）；條件式謂詞使已套用的列被跳過 |
| **競爭情形** | 兩個副本同時通過條件判定 → 兩次相同的更新 → 最終狀態相同 |
| **不需要** | 分散式鎖或領導者選舉 —— 引入它們是為一個無實質後果的競爭付出真實成本 |

依 U1 的 S3，部署目前未設副本數，為單副本。**本條的價值在於讓副本數成為無關變數** —— 日後擴為多副本時本單元不需任何調整。

## 不適用的擴展性面向（逐項判定，不留空白）

| 面向 | 判定 | 理由 |
|---|---|---|
| 資料量成長 | **不適用** | 不新增列、不新增表；本單元只更新既有的一列 |
| 分區／分片 | **不適用** | 單列主鍵存取 |
| 快取 | **不適用** | 啟動期執行一次，無重複讀取可快取 |
| 佇列／非同步化 | **不適用** | 本單元**必須**在服務開始接受請求前完成 —— 非同步化會製造「服務已上線但權限尚未套用」的視窗 |
| 水平擴展策略 | **不適用** | 不新增服務或執行單元（AD-5） |

最後一列的第四項值得強調：這不只是「不需要非同步」，而是**非同步會製造新的正確性問題**。
