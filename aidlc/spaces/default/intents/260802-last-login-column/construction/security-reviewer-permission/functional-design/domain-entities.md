## 本單元觸及的實體：一個，且不改變它的結構

**角色權限矩陣**（`role_permissions`）。**零 DDL、零新表、零新欄位** —— 本單元只改**一列的一個布林值**，以及兩份預設值來源檔中的對應字面值。

這是本單元與 U1 的根本差異：U1 要加欄位（觸發 requirements C-4 的 blocking 同步義務中的 schema 面向），本單元只改 seed 資料的語意（觸發同一條的 seed 面向）。

### 既有結構（依 S8，本單元完全不動）

| 欄位 | 型別 | 本單元的關係 |
|---|---|---|
| 角色 | 字串，**主鍵之一** | 目標值：`Security_Reviewer` |
| 功能識別字 | 字串，**主鍵之一** | 目標值：`J3a` |
| 可檢視 | 布林，非空 | **本單元唯一要翻轉的值**：關閉 → 開啟 |
| 可編輯 | 布林，非空 | **不動**，維持關閉 |
| 可審核 | 布林，非空 | **不動**，維持關閉 |
| 最後異動時間 | 帶時區，`server_default` + **`onupdate`** | 不直接寫；UPDATE 會由 `onupdate` 自動推進 —— 這正是 R3 要避免無謂寫入的原因之一 |
| 最後異動者 | 字串，**可為 NULL** | **作為套用標記**（R2）。本單元讀它決定是否更新，並在真的更新時寫入補丁專屬識別字 |

**主鍵是（角色，功能識別字）複合鍵**，因此目標列的定位是一次單列主鍵查詢，不需索引考量。

## 「最後異動者」欄位的取值語意（本單元的判定依據）

此欄位在既有系統中沒有正式的語意文件，本單元的正確性完全依賴它，故在此定死其四條寫入路徑（依 S4／S5 實測）：

| 路徑 | 值 | 對本單元的意義 |
|---|---|---|
| 程式碼種子寫入 | 固定的系統識別字 | 「從未被人動過」→ 允許更新 |
| SQL 初始化腳本寫入 | **NULL**（腳本的 INSERT 未涵蓋此欄） | 同上 → 允許更新 |
| 本補丁寫入 | 補丁專屬識別字（本單元新增的第三種取值；須為**不可能成為帳號的字面值**） | 「已套用過」→ 跳過（無需動作） |
| 管理員經管理介面調整 | 該管理員的帳號（**整列賦值**：調整任一權限旗標都會寫入） | **不更新**。可能是刻意撤銷（應尊重），也可能是 R2 的死角 → 記為「未套用：該列已被管理員異動」並告警 |

**本單元引入第三種取值**。它必須與既有兩種以及任何可能的管理員帳號都不相同 —— 帳號欄長度上限為 128 字元，選一個帶明確前綴、不可能與真實帳號衝突的識別字即可，具體字串由實作階段決定。

## 目標列的生命週期

| 事件 | 該列的狀態變化 |
|---|---|
| 全新環境、程式碼路徑初始化 | 種子以**新**預設值寫入（開啟），最後異動者為系統識別字。補丁見值已正確 → **跳過**，該列維持種子出處（R3） |
| 全新環境、SQL 路徑初始化 | 腳本以**新**預設值寫入（開啟），最後異動者為 NULL。補丁見值已正確 → **跳過** |
| **既有 staging（本 intent 的實際目標）** | 該列為關閉、最後異動者為系統識別字或 NULL → 補丁**更新為開啟並蓋上補丁標記** |
| 後續每次服務重啟 | 最後異動者為補丁標記 → **跳過** |
| 管理員日後撤銷此權限 | 最後異動者變為管理員帳號、值變為關閉 → 補丁不更新，記為「**未套用：該列已被管理員異動**」（R4 第三態，需人工處置）。**撤銷保留**，但該狀態與 R2 的死角共用同一態 —— 判讀須靠日誌帶出的該欄實際值 |
| 管理員呼叫權限重置端點 | 整張表被刪光並以種子重寫（S4）→ 補丁標記與管理員的**所有**調整一併消失。見下方已知限制 |

## 兩處預設值來源（requirements FR-4.3）

| 來源 | 用於 | 本次改動 | 位置 |
|---|---|---|---|
| 程式碼種子資料 | 程式碼路徑初始化 | 目標列的可檢視值 → 開啟 | S1 |
| SQL 初始化腳本 | SQL 路徑初始化 | 同上 | S1 |

**兩處皆須改，任一處未同步即視為未完成**（requirements FR-4.3）。

### 必須揭露的既有事實

依 S3，程式碼種子資料的檔頭寫著「由 SQL 檔產生（勿手改；改 SQL 後重跑產生腳本）」，但**該產生腳本不存在於 repo**。因此：

1. **本 intent 以手動修改同步兩處**，並在 PR 說明中記載該檔頭契約已失效，使後續維護者不被誤導；
2. **一致性由新增的比對測試承接**（Q1=A）：解析兩份來源、**逐列比對全部 308 列**。依 S2 兩檔皆為可機器解析的字面值，全量比對的實作成本與單列比對幾乎相同；
3. 此測試同時是目前**唯一**鎖住那個已失效「勿手改」契約的機制。

## 已知限制（如實記載，本單元不修復）

| 限制 | 性質 |
|---|---|
| 權限重置端點會抹除補丁標記與管理員的所有調整 | **非本單元引入**（既有行為，S4）。代表「管理員的撤銷得以保留」的保證只在不觸發該端點的前提下成立 |
| 權限變更的稽核記錄易失（保存期約等於兩次部署間隔） | requirements C-7 的既有約束，本 intent 不修復 |
| 公開未認證的角色目錄端點也會呼叫種子函式（S4） | 空表的種子行為可在啟動後被外部觸發。本次不致出錯（預設值已改為開啟，觸發後結果與補丁一致），但**不在本單元的時序模型內**，如實標出 |
| **目標列若在部署前已被管理員動過，本補丁永不套用**（承接上游 **M1-a**） | **本輪新承接**。實測管理員的更新分支為**整列賦值**，故調整任一權限旗標都會留下管理員帳號。不改寬謂詞（改寬會覆寫管理員調整，與 AD-7 衝突）；以 R4 的第三態告警 + 部署後人工核對承接 |
| 補丁識別字與使用者帳號共用同一欄位（承接上游 **m5**） | 帳號無格式約束，理論上可與識別字碰撞；且本形狀為**每列單次使用**，後續補丁不得沿用同一謂詞 |
| 本單元在既有測試路徑上無自動化驗證 | 見 `business-logic-model.md` 的驗證缺口段落 |
