# Performance Test Instructions

## 判定：本 intent 不執行效能測試

**沒有可測的目標。** 五個單元的 NFR 文件逐份明寫「全部是**設計上可推導的界限**，非量測結果」，且**沒有任何一條 NFR 給出數值目標**（無回應時間、無吞吐、無並發數）。對沒有目標的東西跑負載測試，產出的數字無從判定通過或失敗。

這是判斷，不是省略 —— 理由如下：

| 面向 | 為何不設數值目標 |
|---|---|
| 本 feature 的效能主張 | 全部是**上界**而非速度：單次回應至多 `page_size` 筆、寫入至多每 5 分鐘一次、每次請求兩個既有索引可服務的查詢。三者皆為**結構性**保證，由程式碼本身而非量測承載 |
| 系統規模 | 目前 12 個帳號。任何負載數字在這個規模下都不具參考價值 |
| 既有基線 | 本 repo 從未做過效能量測，沒有可比較的基線；單獨為本 feature 建立一個，其數字無從解讀 |

## 分頁的效能收益是**可推導**而非可量測的

| 帳號數 | 分頁前單次回應 | 分頁後 |
|---|---|---|
| 12 | 12 筆 | 12 筆（單頁） |
| 10,000 | **10,000 筆** | 20 筆 |

收益不在「更快」，在「回應大小不再隨帳號數成長」。這一點以 `test_page_size_bounds_the_response` 的斷言承載，不需要負載測試。
