# 安全需求 — admin-page-column（U3）

> **上游輸入**：本單元的 `../functional-design/business-logic-model.md`（Revision 1 的分頁狀態邏輯模型與**決策表：哪些操作觸發哪種抓取**）、`../functional-design/frontend-components.md`（Revision 1 的三種抓取路徑、三處整份重抓皆須改、正規化收斂在抓取函式內、併發保護）。本檔的每一條 NFR 皆為上述功能規則的非功能面展開，不新增行為。

## ADR-0006 四面向逐項判定

| 面向 | 判定 | 影響與處置 |
|---|---|---|
| **IAM** | **不適用** | 本單元不做任何授權判斷。頁面的可見性由既有的路由守衛與後端端點的權限檢查決定；欄位級權限控制已明文列為 Won't Have（requirements FR-4.2） |
| **Encryption** | **不適用** | 不新增儲存、不新增傳輸通道。所有資料經既有的 HTTPS ／ Cloudflare Tunnel 邊界 |
| **Network exposure** | **不適用** | 不新增任何端點或外部呼叫。分頁只是在**既有**的清單請求上多帶一個查詢參數 |
| **Audit logging** | **不適用** | 純呈現層，不產生狀態異動 |

## S-1 不在前端做授權判斷，也不依賴前端隱藏來保護資料

分頁控制與最後活動時間欄的可見性**不構成任何安全邊界** —— 能呼叫端點的人本來就拿得到資料。前端的 `can('J3a','edit')` 只用於**決定要不要渲染編輯控制項**，不作為授權；真正的授權在後端每個端點的依賴鏈上。

這條寫下來是因為它容易被誤解成「隱藏了就安全了」。

## S-2 不把時間值以外的資料寫進 URL 或本地儲存

分頁狀態（目前頁次）**只存在 React state**，不寫入網址、不寫入 `localStorage`。

> 「分頁狀態是否反映在網址」是線框明列的**未定案**項目，本 intent 不做。附帶的安全性質是：不入網址則不會出現在瀏覽紀錄、分享連結或 referrer 中 —— 但這是不做的**附帶結果**，不是不做的理由（理由是它不影響任何 AC）。

## S-3 錯誤訊息不得洩漏後端內部細節

沿用既有形狀：以 `data.detail` 取後端提供的訊息，不拼接堆疊或內部識別字。非法分頁參數的 422 在正常 UI 路徑不可達（控制項只送合法頁次），僅在手動改網址時出現。
