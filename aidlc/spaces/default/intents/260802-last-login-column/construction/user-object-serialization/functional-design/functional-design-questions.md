## Q1. 如何保證三個構造點都帶出兩個新欄位

> `component-methods.md` C-4 明文列為「契約（二擇一，Construction 定實作）」。

A. **選項一：兩個新欄位不設可靜默通過的預設值** — **（建議）**
   - 新欄在回應模型上為必填，漏傳即在構造時拋錯，讓問題在測試而非生產暴露。
   - 查證後有兩個非顯而易見的優勢：
     - **共用工廠函式拿不到 C-4 寫的那個簽章**。依 S4，清單端點的 `requested_role` 需要一次額外的 DB 查詢，另兩處完全不傳 —— `(使用者物件, 當下時刻)` 的簽章重現不了這個差異，工廠得多接參數或多接 session。
     - **工廠函式會順手碰到範圍外的缺陷**。依 S2／S3，那兩處漏傳 `requested_role` 是既有缺陷，已被階段邊界驗證明確劃在本 intent 範圍外；走工廠就必須就地決定補或不補。
   - 另與 `team.md ## Code Style`「修改 `user_router.py` 就地沿用既有形狀，不趁機夾帶抽取」方向一致。
   - 代價：三處仍是手寫；將來新增第四個構造點仍靠人記得 —— 但會在**構造時失敗**，不是靜默。

B. **選項二：三處改走共用工廠函式**
   - 好處：分歧在結構上不可能發生。
   - 代價：見上 —— 簽章必須比 C-4 寫的更寬；且必須就地決定那兩處要不要補 `requested_role`（補了超出範圍，不補則工廠內部仍要分歧）。

## Q2. 逾期判定的「當下時刻」如何取得

> C-1 的兩個判定**刻意把當下時刻參數化**（U1 定案），呼叫端必須提供。

A. **每個請求取一次，整張表共用** — **（建議）**
   - 進入端點時取一次，所有列以同一個瞬間判定。
   - 好處：同一張表的逾期標示彼此可比較，不會出現「同一次回應中兩列用不同基準判定」；且測試只需注入一個時刻就能控制整張表的判定結果。
   - 代價：無。
   - **補充約束（reviewer iteration 1 補上）**：該時刻**必須帶時區（UTC）**。U1 的規則層明載 naive 值與資料庫讀回的帶時區值相比較會拋型別錯誤；由於整次回應共用同一個時刻，取錯會讓三個端點的第一次比較**全部**失敗 —— 不是偶發，是必然且全面。

B. **每列各取一次**
   - 代價：同一次回應內各列基準不同；且測試要控制判定結果必須 patch 系統時鐘而非傳參，與 C-1 刻意參數化的可測性設計相衝突。

## Q3. 端點測試對「回應欄位集合」的斷言嚴格度

> C-4 逐字記載：此斷言是本 intent 中**唯一**能自動抓到「某個端點漏了欄位」的機制（requirements NFR-5、team-practices 規則 B）。

> **Revision（reviewer iteration 1，2026-08-10）**：本題**定案不變**（仍為完全相等），但題幹與選項描述對這個斷言**能防什麼**的認定是錯的，已更正。
>
> - **錯在哪**：實測三個端點皆宣告 `response_model`，**回應 JSON 的 key 集合由回應模型的欄位宣告決定，與構造點傳了什麼無關**。有預設值的欄位不論傳不傳都會出現在 key 集合中。
> - **因此**：題幹引用的「C-4 點名這是唯一能自動抓到某端點漏了欄位的機制」與選項 A、B 描述中「S2 已經真的發生過」的推論**皆不成立** —— S2 的既有缺陷根本不是「少了欄位」，而是**值被靜默預設為 `null`**。
> - **真正的分工**：構造點漏傳**必填**欄位由 **R1 的必填宣告**在構造當下擋下（結構性保護，非測試）；值被靜默預設為 `null` 由 **AC-1.5 要求的值斷言**擋下；欄位集合斷言防的是**回應模型本身被增刪欄位**。三者互補，本單元三者皆需。
> - **A 仍為正確選擇**（多抓一類 schema 層回歸），只是它的作用範圍比原描述窄。**原答案與選項本文均不改寫**（依既有慣例：不回改已作答的紀錄），但下方 A／B 描述中**不成立的句子已就地標註**，避免同一題內前後矛盾。

A. **完全相等：欄位集合逐字比對** — **（建議）**
   - 斷言回應的 key 集合與預期集合**完全相等**，三個端點各一支測試。
   - 同時抓到「少了欄位」與「多了沒預期的欄位」。依 S2，這三個端點**已經真的發生過**「新增欄位時漏掉另一個欄位」的失敗模式，包含式斷言抓不到它。
   - 代價：日後合理新增欄位時測試會紅，必須在同一個 PR 更新預期集合 —— 這是契約測試應有的行為。

B. **包含即可：只斷言兩個新欄位存在**
   - 好處：不會因其他人新增欄位而紅。
   - 代價：抓不到「新增欄位時弄丟了既有欄位」這類回歸 —— 而那正是本檔 S2 記載的、這三個端點已發生過的事。
