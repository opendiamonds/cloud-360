## 評估結論

**可行（conditional GO）**。本功能在現有系統上可以實作，無外部阻塞 [Q5]，但可行性建立在四個已確認的前提上：

1. **證據事件已定錨為「任何有效活動」**：任何以有效憑證發出的系統請求都算「帳號仍在使用」的證據 [Q1]；欄位語意隨之確認為「最後活動時間」，原始請求的「最後登入時間」據此重新表述 [Q8]。
2. **上線前空窗已被接受**：系統今日沒有任何登入或活動紀錄，且無可回填的來源；上線時所有既有帳號的值必然為空，空值顯示「無紀錄」[Q2] [code:C1]。
3. **變更套用路徑已選定**：沿用既有慣例（服務啟動時自動補齊結構＋以最小範圍的更新語句調整權限值），不重跑整份資料庫初始化腳本 [Q3] [code:C4] [code:C5]。
4. **權限擴張風險已接受並記錄**：`Security_Reviewer` 取得整頁檢視權限的擴張，其風險處置為「接受」，證據落點在本 stage 的 raid-log [Q7]（intent 階段的既定決策不重開 [intent:Q10/Q12]）。

## 技術可行性

以能力層描述現況與落差（技術細節的出處見問題檔 Sources）：

| 面向 | 現況 | 落差與可行性 |
| --- | --- | --- |
| 活動紀錄 | 系統完全沒有登入或活動時間的既有紀錄，也沒有任何可回填來源 [code:C1] | 需從零建立記錄能力；歷史不可回填，空窗由 [Q2] 接受 |
| 認證模型 | 無狀態短期憑證（8 小時效期、無更新機制）[code:C2] | 若只記登入，值與實際活動最多差 8 小時；[Q1]=C 選擇記錄任何活動，迴避此誤差 |
| 資料儲存 | 使用者資料表無任何相關欄位 [code:C3] | 單一欄位即可承載「最後一次」語意，且不阻擋未來擴充為歷史紀錄 [intent:Q9] |
| 管理介面 | 既有使用者管理頁為表格式清單，可延伸新欄位 | 展示面為機械性擴充，可行性無疑慮 |
| 權限矩陣 | 稽核角色今日不可見使用者管理頁；權限預設值存在兩處來源且須同步 [code:C6] | 翻轉一筆權限值即可開通，但觸發部署資產同步義務 [memory:M1] |

**成本警示（記錄頻率）**：「任何有效活動都算」意味每個帶憑證的請求都可能觸發一次寫入 [Q1]。在本平台的使用規模下屬可承受，但寫入頻率的緩解手段（如節流、彙整）是設計階段的必答題 — 已列入 raid-log 風險 R1，本階段不預作設計決定。

## 驗證方式

- 成功指標的驗證採**受控測試**：以測試帳號實際產生活動，比對介面顯示值與活動發生時刻 [Q6]；比對對象為任何活動（含登入）[Q6a]。
- 不要求第二資料來源（如結構化 log 交叉比對）[Q6]；此選擇解消了 intent 成功指標「可與後端紀錄對照驗證」在「系統沒有既有紀錄可對照」現況下的自證困境 [intent:Q3] [code:C1]。

## 風險分析

完整風險、假設、議題與依賴見同目錄 `raid-log.md`；關鍵三項：

- **R1 記錄頻率成本**（緩解留設計階段）[Q1]
- **R2 資料庫初始化腳本重跑會重置權限設定**（以 [Q3] 的路徑選擇迴避，並依 [memory:M1] 在部署文件記載）[code:C5]
- **R3 稽核角色權限擴張大於稽核欄位本身**（風險接受，本紀錄即證據）[Q7] [memory:M4]

## Assumptions & Open Questions

- [assumption] 「超過 N 天未活動」的門檻 N 仍未定義，承襲 intent 階段的未決項；成功指標在 N 決定前不可完整驗證 [intent:Q3]
- [assumption] 活動資料有保存上限，但上限值未定，留待 requirements-analysis 決定 [Q4]
- [assumption] 單一欄位覆寫模式下，「保存上限」的實際含意（例如帳號停用後何時清除該值）尚未定義，隨 [Q4] 的值一併釐清
- [assumption] 本平台為內部工具，登入／活動時間不受外部法規框架（如個資保護法規的跨境或在地化要求）約束；此判斷未經法務確認 [Q4]
- [assumption] （開放問題）語意由「最後登入」改為「最後活動」後 [Q8]，上游 intent-statement 的「最後登入」表述不回改；若日後稽核方堅持登入語意，需回到 [Q1] 重新定錨
