**carol 這一列驗證 AC-2.5**：兩個破折號並排，外觀相同但可及性不同。依 [Q2] 的定案，區分僅落在可及性層面：螢幕閱讀器會讀出活動時間欄的說明，角色欄則不會；鍵盤 Tab 只會停在活動時間欄的破折號上。

**dave 這一列驗證雙 amber 的最壞情境**。這個組合是**真實可達的資料狀態**，不是理論邊角：既有的認證與登入流程只檢查帳號是否啟用，**不檢查授權狀態** —— 所以一個待授權帳號可以先登入產生活動紀錄，之後 90 天未獲核准也未再活動，就會同時是「待授權」與「逾期」。

畫出來後的判定：**可接受，不需改色**。三項依據：

1. **兩個 amber 元素隔了一整欄**（角色欄在中間），不會形成連續色塊
2. **只有活動時間欄帶 `(!)` 圖示** —— 圖示是逾期的主要訊號，授權狀態欄沒有它
3. **兩者語意本就同類**（都是「需要人處理」），同時亮起時傳達的訊息一致而非衝突：這個帳號既沒獲核准、也很久沒動了 —— 對稽核者而言這是**強化**而非干擾

若實作後仍覺辨識困難，調整方向是改變其中一者的呈現形式（如圖示或字重），不需推翻「用既有語意色」的原則。

## 小螢幕 — 卡片式佈局（768px 以下）

```
+------------------------------------------+
| alice                        [on]  [調整]  |
| 授權狀態: 已核准                                |
| 角色: Platform_Admin                       |
| 最後活動: 2026-08-07 14:52                   |
+------------------------------------------+
| dave                         [on]  [調整]  |
| 授權狀態: 待授權                                |
| 角色: —                                    |
| 最後活動: (!) 2026-03-15 08:30               |
+------------------------------------------+
| carol                        [on]  [調整]  |
| 授權狀態: 待授權                                |
| 角色: —                                    |
| 最後活動: —                                  |
+------------------------------------------+
```

<!-- Text fallback: 小螢幕以一帳號一卡片呈現。卡片首行為使用者名稱與啟用切換、角色調整入口；其下逐行列出授權狀態、角色、最後活動時間。dave 卡片展示待授權與逾期同時出現的情境；carol 卡片展示角色與活動時間皆為破折號的情境。標示語彙與桌面完全一致。 -->

- 一帳號一卡片；卡片內欄位以「標籤: 值」逐行呈現，**順序與桌面表格欄序一致**（授權狀態 → 角色 → 最後活動），使掃讀慣性在兩種佈局間不變
- 逾期／無紀錄的標示規則與桌面**完全相同**（同一組樣式語彙），滿足 stories AC-4.2
- 既有操作（角色調整、啟停用）在卡片首行保留；觸控目標不小於 44x44
- **在雙 amber 的 dave 卡片中，兩個 amber 元素相隔一行**（角色行在中間），與桌面版相隔一欄的效果相當

**與已核可線框的一處對齊修正**：`wireframes.md` 的卡片順序為「角色 → 授權 → 最後活動」，與該檔自身的桌面表格欄序（授權狀態 → 角色 → 最後活動）**不一致** —— 這是線框階段的既有瑕疵。本站將卡片順序對齊為與表格一致，並把標籤補全為「授權狀態」（與表頭用字相同）。

此為**對齊修正而非本站新定案**：它不改變任何已核可的決策內容（欄位集合、標示規則、佈局形式皆不變），只消除同一份文件內部的順序不一致。依專案慣例，下游發現的上游瑕疵不回改已核可 artifact，以本站的紀錄向下游傳遞。

## 畫面態由五態增為七態

既有的五態表**內容不變**，本次新增**兩態**。新增而非改寫的理由：兩者在本 intent 之前**皆不可達** —— 清單不分頁時，只要有帳號就一定有內容（無空清單），也不存在「切頁」這個動作（無切頁進行中）。是分頁把它們從不可能變成可能。

| 態 | 呈現 | 依據 |
| --- | --- | --- |
| **空清單（本次新增）** | 容器內置中「這一頁沒有資料。」＋「回到第 1 頁」；**分頁控制照常呈現** | stories AC-5.4、本站定案 8 |
| **切頁進行中（本次新增）** | 容器內顯示既有的「載入中…」訊息；**分頁控制照常呈現於容器外**、目前頁次仍可辨識、整組標記忙碌狀態 | stories AC-5.10、本站定案 9 |

**與既有「載入中」態的區別**：既有的載入中態是**初次載入**（整個容器連同尚未存在的分頁控制都不呈現）；切頁進行中是**已有內容後的更新**（分頁控制已存在且必須留在畫面上）。兩者的容器內呈現相同、控制項的去向不同，故為兩個態而非同一個。

> `project.md` 的「加欄型 feature 沿用既有狀態呈現、不重新設計」correction 在此**不適用** —— 空清單不是既有狀態，沒有可沿用的既有模式。本站因此是在**新增**兩個態，不是在改版既有的五態。
