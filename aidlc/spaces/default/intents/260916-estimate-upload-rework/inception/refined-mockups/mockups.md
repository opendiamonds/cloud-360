## 3. M2 — 上傳中與雲別判定（Q1=C）

檔案落地後，拖放區下方長出一列判定結果，每檔一列。

```
┌──────────────────────────────────────────────────────────────┐
│   ┌────────────────────────────────────────────────────┐     │
│   │            把估價表拖進來，或點擊選擇檔案            │     │  ← 已達 3 檔時整區 disabled
│   └────────────────────────────────────────────────────┘     │
│                                                              │
│   my-aws-estimate.csv      [ AWS      ▾ ]  已解析 42 列   ✕  │
│   azure-export.xlsx        [ Azure    ▾ ]  解析中…        ✕  │
│   estimate-final.csv       [ 請選擇雲別 ▾ ] ⚠ 無法判定    ✕  │
│                            └─ 需要你指定，否則不會解析        │
└──────────────────────────────────────────────────────────────┘
```

- 雲別一律以**下拉呈現且永遠可改**，不論系統是否判定成功。FR1.5 的「判不出來才問」在此退化為更溫和的形式：判定成功時下拉已預選、判定失敗時預設為未選並以 ⚠ 標示。這讓「判錯」和「判不出來」共用同一個修正動作，不需要兩套 UI。
- 未選雲別的檔案**不送解析**，也不建立雲別卡片。
- ✕ 為移除；移除已解析的檔案會一併移除其卡片。

## 4. M3 — 主畫面摺疊態（Q2=C）

```
┌──────────────────────────────────────────────────────────────┐
│  雲端估價分析          僅自己可見    [ 歷史 ]  [ 分享 ]      │
├──────────────────────────────────────────────────────────────┤
│  ┌────────────────────────────────────────────────────┐      │
│  │ ＋ 再上傳一份估價表                                 │      │  ← 已有資料時拖放區收合為單行
│  └────────────────────────────────────────────────────┘      │
│                                                              │
│  ▸ AWS          42 項      USD 12,480.00      ✓ 檢查通過      │
│  ────────────────────────────────────────────────────────    │
│  ▸ Azure        31 項      USD  9,215.40                     │
│                 ⚠ 3 列無法辨識 · 總額未經核對                  │
│  ────────────────────────────────────────────────────────    │
│  ▸ GCP          28 項      USD  8,002.15      ⚠ 幣別不一致    │
│  ────────────────────────────────────────────────────────    │
│                                                              │
│  ┌── 檢查結果 ───────────────────────────────────────────┐    │
│  │ ✓ AWS：明細加總與表上總額相符（差異 0.02%）            │    │
│  │ ⚠ Azure：有 3 列無法辨識，已跳過總額對帳                │    │
│  │ ⚠ GCP：同一份估價表中出現 USD 與 TWD 兩種幣別           │    │
│  │ ⚠ GCP：有 2 列數量非正值                               │    │
│  └──────────────────────────────────────────────────────┘    │
│                                                              │
│  ┌── AI 建議 ────────────────────────────────────────────┐    │
│  │ 由 AI 產生，請自行核對                                 │    │
│  │ ░░░░░░░░░░░░░░░░░░  正在產生…                          │    │
│  └──────────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────────────┘
```

**摺疊態的標頭必須攜帶三樣東西**：雲別、項數與總額、機械檢查摘要。第三樣是 FR3.2 得以在摺疊狀態下成立的唯一依據——`refined-mockups-questions.md` 後果一的處置。若標頭省略「N 列無法辨識」，這個版面就違反 FR3.2。

「檢查結果」與「AI 建議」是**兩個標題分明的區段**（Q4=A），後者固定帶「由 AI 產生，請自行核對」的註記。FR4.5 要求使用者能分辨結論來源，區段標題加註記是此處的實現方式。

**機械檢查的三類結果都在此區段現身**（FR4.1 幣別一致、FR4.2 數量正值、FR4.3 總額對帳）。上例四條依序示範了對帳通過、因無法辨識列跳過對帳、幣別不一致、數量非正值。

**但三類的呈現層級不同**，因為它們的判斷對象不同：

| 檢查 | 判斷對象 | 摘要層 | 明細列層 |
|---|---|---|---|
| FR4.1 幣別一致 | 逐列（哪幾列的幣別異於多數） | ✓ 說明有幾列 | ✓ 金額欄以 amber 標示並顯示其幣別 |
| FR4.2 數量正值 | 逐列（哪幾列數量非正） | ✓ 說明有幾列 | ✓ 數量欄以 amber 標示並顯示原值 |
| FR4.3 總額對帳 | **整張表**（單一算術結論） | ✓ 差異百分比或「未對帳」 | ✗ **不標示** |

FR4.3 沒有列層呈現，不是設計上的省略——它比對的是「全部列的加總」與「表上總額」，這個結論不屬於任何一列。它的落點是明細表**表尾的三行**（見 §5），不是列內。硬要在列層標示它，等於要求實作者發明一個需求沒有的概念。

前兩類則必須同時做兩層：只做摘要層會讓使用者知道「有 3 列有問題」卻無從定位是哪 3 列。

僅上傳一朵雲時，只出現一張卡片；跨雲比較類建議在 M5 顯示為「資料不足」（FR5.3）。

## 5. M4 — 雲別卡片展開態（Q5=A）

```
│  ▾ Azure        31 項      USD 9,215.40                      │
│     ⚠ 3 列無法辨識 · 總額未經核對                              │
│  ┌──────────────┬──────────────┬────────┬─────────────┐      │
│  │ 品項          │ 規格          │   數量  │       金額   │      │
│  ├──────────────┼──────────────┼────────┼─────────────┤      │
│  │ Virtual Mach…│ D4s v5, 東亞  │      4 │   2,880.00  │      │  ← 有描述則顯示描述
│  │              │ SKU DZH…     │        │             │      │  ← 原始 SKU 作副標
│  │ Blob Storage │ Hot LRS 2TB  │      1 │     412.30  │      │
│  │ ░ Load Bala… │ ░ Standard   │   ░ ─  │  ░ 無法辨識 ▸│      │  ← 淡色底，可展開看原始文字
│  │ SQL Database │ GP_Gen5_4    │      2 │   3,104.10  │      │
│  └──────────────┴──────────────┴────────┴─────────────┘      │
│                                    小計    USD 9,215.40      │
│                                    表上總額 USD 9,215.40      │
│                                    ⚠ 因 3 列無法辨識，未對帳   │
```

- 無法辨識的列**留在原始順序上**，不抽出、不下沉。抽出會破壞使用者拿畫面對照原始估價表的能力，而對照正是他發現解析出錯的主要手段（FR10 的品質檢查建議只是輔助）。
- 該列淡色底 + 金額欄顯示「無法辨識」+ ▸ 展開看保留的原始文字（FR2.2）。
- 表尾三行：明細小計、表上總額、對帳結論。**存在無法辨識列時第三行固定為「未對帳」**，不顯示百分比差異（FR4.4）。全數解析時第三行為「差異 X.XX%（門檻 0.5%）」。

## 6. M5 — AI 建議區塊三態（Q3=A）

解析完成後建議才開始產生，區塊有三種狀態：

**產生中**（骨架載入，NFR2）
```
│  ┌── AI 建議 ────────────────────────────────────────────┐    │
│  │ 由 AI 產生，請自行核對                                 │    │
│  │ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░                         │    │
│  │ ░░░░░░░░░░░░░░░░░                                      │    │
│  │ 正在產生建議…（通常需要 1–3 分鐘）                      │    │
│  └──────────────────────────────────────────────────────┘    │
```

**完成**（三類建議一次填入，Q3=A 而非 D）
```
│  ┌── AI 建議 ────────────────────────────────────────────┐    │
│  │ 由 AI 產生，請自行核對                                 │    │
│  │                                                       │    │
│  │ 省錢建議                                               │    │
│  │ • AWS 的 4 台 m5.2xlarge 為隨需計價，改用一年期 …      │    │
│  │                                                       │    │
│  │ 跨雲比較                                               │    │
│  │ • 同等規格的運算資源，GCP 較 AWS 低約 12% …            │    │
│  │                                                       │    │
│  │ 品質檢查                                               │    │
│  │ • Azure 的 Blob Storage 單價偏離目前牌價約 30%，…      │    │
│  └──────────────────────────────────────────────────────┘    │
```

**部分未提供**（FR5.2）
```
│  │ 跨雲比較                                               │    │
│  │ ⓘ 資料不足——只上傳了一朵雲的估價表，無法比較。          │    │
```

三類子標題**固定全部出現**，即使某類沒有內容。缺內容時顯示「本期未提供」或具體原因（如上方的資料不足），不隱藏子標題——隱藏會讓使用者無從判斷是沒建議還是壞掉了。

AI 建議中若引用了官網現價（CAP-8／FR5.6），該價格只出現在**建議文字內**，不回寫明細表（ADR-0017 §8 界線）。

## 7. M6 — 歷史上傳抽屜（Q6=A）

自右側滑入，寬約 400px，遮罩其餘畫面。

```
                          ┌───────────────────────────────┐
                          │  歷史上傳                  ✕  │
                          ├───────────────────────────────┤
                          │  ● 2026-09-16 14:32  目前檢視  │
                          │    AWS、Azure、GCP             │
                          │  ───────────────────────────  │
                          │  ○ 2026-09-14 09:10           │
                          │    AWS、Azure          [檢視]  │
                          │  ───────────────────────────  │
                          │  ○ 2026-09-02 17:45           │
                          │    GCP                 [檢視]  │
                          │                        [刪除]  │
                          └───────────────────────────────┘
```

- 一次只能檢視一個版本。點「檢視」關閉抽屜並把主畫面切到該版本，頁首顯示「檢視 2026-09-14 的版本 · 回到最新」。
- **沒有勾選框、沒有「比較選取的版本」**。FR6.3 明訂不得並排比較，而並排比較最常見的入場方式就是清單上的多選——不放勾選框是這條界線在 UI 上的具體落實。
- 刪除為使用者主動行為（FR6.4），需二次確認。

## 8. M7 — 分享 modal（Q6=A、FR6.6）

沿用 `ShareModal.tsx` 的版面與樣式，只換資料來源（估價表而非架構圖）。**版面不動，行為要補**——`ShareModal` 目前無 `role="dialog"`、`aria-modal`、focus trap 或 Escape 關閉，本站要求一併修補（Q7=A），細節見 `accessibility-checklist.md` A11。

**隱私狀態指示（FR6.5）**：估價表預設僅上傳者可見。頁首在標題右側顯示當前狀態的文字徽章——未分享時為「僅自己可見」，已分享時為「已與 N 人分享」。沒有這個指示，使用者無從得知自己的估價表現在誰看得到；FR6.5 的「預設私密」若在畫面上完全沒有痕跡，使用者只能靠記憶或猜測。徽章為純文字（不只用鎖頭圖示），符合 `accessibility-checklist.md` A4 不倚賴單一感官的要求。

**徽章不可點，分享按鈕是唯一入口。** 兩者都能開 modal 會形成語意不明的雙入口（Tab 序上還相鄰），使用者得自行推斷兩者差異——而它們根本沒有差異。徽章負責「說出現況」，按鈕負責「改變現況」，職責不重疊。這也讓徽章不必是 `<button>`，少一個互動元件與其無障礙負擔。

## 9. M8 — 錯誤狀態

| 情境 | 呈現位置 | 文案要點 |
|---|---|---|
| 單檔超過 5 MB | 該檔在判定列上以紅字標示，不計入 3 檔配額 | 指出實際大小與上限 |
| 超過 3 檔 | 拖放區 disabled 並顯示提示 | 說明需先移除既有檔案 |
| 副檔名不符 | 同單檔超限 | 列出接受的副檔名 |
| 檔案內容與副檔名不符（FR1.4 魔術位元組） | 該檔判定列紅字 | 明說內容不是宣稱的格式，不要只說「上傳失敗」 |
| 整份解析不出任何一列 | 該雲別卡片取代為錯誤卡 | 說明可能原因（非官方匯出格式），提供移除 |
| 建議產生逾時（>5 分鐘，NFR1） | AI 建議區塊 | 明細與檢查結果**保持可用**，僅建議區顯示逾時與重試 |

最後一列是 Q3=A 漸進式呈現換來的具體好處：建議壞掉不會連帶讓明細不可用。

## 10. M9 — 官方估價教學彈窗（FR12）

點 M1 的三雲按鈕開啟 dialog（非直接開新分頁）。每雲 2–3 頁：官網截圖＋呼出「建立估價／加入服務／匯出」位置；文案標明 AWS CSV、GCP CSV、Azure XLSX。最後一頁提供該雲官方計算機連結。截圖為 `frontend/public/cost-guides/` 靜態檔，執行期不抓頁。

規格欄（M4）：有 `spec_description` 時主列顯示描述、下一行灰色 `SKU {spec}`；查不到則只顯示檔案規格。

## Assumptions & Open Questions

**假設**

- **A-M1**：`/cost` 的 landing 邏輯（無參數時導向最近一次上傳）可原樣沿用，僅置換資料來源。取自 requirements-analysis Q8=A，未逐行驗證既有實作。
- **A-M2**：估價表的幣別以原始檔案為準，不做換算。M3 的「幣別不一致」是檢查項而非轉換觸發點。FR4 未要求換算，此處不自行加入。
- **A-M3**：三類 AI 建議一次填入（Q3=A）意味著後端以單一回應交付三類建議。若 LangGraph 的實作最終為串流或分段回傳，Q3=D 的版面（各自填入）才是正確的；此假設須在 domain-design 對齊。
- **A-M4**：**FR6.1「估價表可選綁定架構圖」的 UI 在本站刻意缺席**，不是遺漏。`requirements.md` OQ3 記載此綁定的語意尚未確定（綁定後兩者的生命週期、刪除連動、以及是否影響可見性皆未定），在語意定案前設計畫面只會產出要被推翻的東西。待 domain-design 明確語意後補設計。本條依審閱意見 R-02 補記。

**待決**

- **OQ-M1**：`ShareModal` 的無障礙修補構成本 intent **第五處 scope 漂移**（前四處見 requirements-analysis OQ1）。它掛在 PU-13 之下但未計入其原始估算。落點與工作量交由 delivery-planning 裁決。
- **OQ-M2**：抽屜（drawer）為程式庫中不存在的新元件型別。是否值得為單一用途新增一個元件型別、或以既有 modal 承載歷史清單，留給 functional-design 在看過實作成本後複核。本站依 Q6=A 定案為抽屜。
- **OQ-M3**：M3 摺疊態標頭需顯示機械檢查摘要，但 FR4 未定義摘要的優先序——當一朵雲同時有「無法辨識列」與「幣別不一致」時，標頭空間只夠一條。排序規則交由 functional-design。

### 三處修正的複核

**R-04（FR 編號寫反）**：§4 說明括號現在讀作「FR4.1 幣別一致、FR4.2 數量正值、FR4.3 總額對帳」，與 `requirements.md` 完全一致。Resolved。

**R-05（過度宣稱列層呈現）**：「三類皆同時在摘要層與明細列層呈現」已刪除，取而代之的是一張分層表格，明確區分：FR4.1/FR4.2 判斷對象為逐列（指定具體列上 amber 的欄位與顯示內容）；FR4.3 判斷對象為整張表（列層 ✗ 不標示，並附理由：比對結論不屬於任何一列，落點在表尾三行）。這個解法正確且可讀——開發者再也不需要猜「幣別不一致要 amber 哪幾列」。Resolved。

**附帶觀察（非阻擋）**：FR4.1 的列層規格「金額欄以 amber 標示並顯示其幣別」隱含每個 `LineItem` 帶有幣別欄位，這樣前端才能比對哪幾列與多數幣別不符。`interaction-spec.md` §4 的 `LineItem` 型別未定義具體欄位形狀，這是 **domain-design 的邊界問題**，不是 mockups 的職責——mockups 已正確指定「哪欄、顯示什麼、什麼視覺效果」，資料模型由 domain-design 確認。不開新找項。

**R-06（PrivacyBadge 雙入口）**：`interaction-spec.md` §7b 已將 PrivacyBadge 改為純展示：Category 由 `display / navigation` → `display`，無 `onClick` prop，ARIA role 為 `<span>` 不進 Tab 序，Focus management 標為「不適用」。§9 鍵盤導覽順序同步更新，徽章標註「（非互動，不進 Tab 序）」。`mockups.md` §8 補記「徽章不可點，分享按鈕是唯一入口」與職責劃分理由。三處互相一致。Resolved。
