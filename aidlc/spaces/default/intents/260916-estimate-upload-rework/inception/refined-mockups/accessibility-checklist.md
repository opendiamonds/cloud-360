# Accessibility Checklist：C1 估價表上傳

目標等級 **WCAG 2.1 AA**（Q7=A），涵蓋 `/cost` 新畫面**與** FR6.6 沿用的 `ShareModal`。

本檔為驗收清單，每項須在 build-and-test 階段逐條查核。狀態欄在本站一律為「待驗」——refined-mockups 只定義目標，不做實作查核。

---

## 起點：既有程式碼的無障礙現況

這不是從零開始，是從負數開始。實測結果：

| 檔案 | `role=` / `aria-*` 出現次數 |
|---|---|
| `ShareModal.tsx`（136 行，FR6.6 指定沿用） | **0** |
| `CostPage.tsx`（964 行，將整檔重寫） | 1 |
| `PaginationControl.tsx` | 7（全 repo 最完整） |
| `ChatBox.tsx` | 5 |
| `Sidebar.tsx` | 5 |

`ShareModal` 的 0 是本清單 A11 區段存在的原因。**沿用一個零無障礙標記的 modal，等於把缺口複製到新功能上**——這是 Q7=A 要處理的具體對象，不是抽象的「品質提升」。

## A1 — 語意結構

| # | 項目 | 依據 | 狀態 |
|---|---|---|---|
| A1.1 | 頁面有唯一 `<h1>`，標題層級不跳階 | 1.3.1 | 待驗 |
| A1.2 | 明細表為真實 `<table>`，含 `<thead>` 與 `<th scope="col">` | 1.3.1 | 待驗 |
| A1.3 | 「檢查結果」與「AI 建議」為 `<section aria-labelledby>` | 1.3.1、FR4.5 | 待驗 |
| A1.4 | 拖放區以真實 `<input type="file">` + `<label>` 實作，不自造 `role="button"` | 4.1.2 | 待驗 |
| A1.5 | mobile 卡片化**不破壞 `<table>` 語意**（用 grid 重排，不用 `display:block`） | 1.3.1 | 待驗 |

A1.5 是 Q8=B 最容易做錯的一步。把 `<table>` 改成 `display:block` 是最短的卡片化路徑，也會直接讓螢幕閱讀器失去列欄關聯——視覺上看不出差別，所以不會有人發現。

## A2 — 鍵盤操作

| # | 項目 | 依據 | 狀態 |
|---|---|---|---|
| A2.1 | 所有互動元素可用 Tab 到達，順序符合視覺順序 | 2.4.3 | 待驗 |
| A2.2 | 不使用正值 `tabindex` | 2.4.3 | 待驗 |
| A2.3 | 卡片標頭以 Enter／Space 展開摺疊 | 2.1.1 | 待驗 |
| A2.4 | 抽屜與 modal 以 Escape 關閉 | 2.1.2 | 待驗 |
| A2.5 | 抽屜與 modal 開啟時 Tab 在其內循環（focus trap） | 2.1.2 | 待驗 |
| A2.6 | 無鍵盤陷阱（focus trap 之外） | 2.1.2 | 待驗 |
| A2.7 | 拖放區有非拖放的替代操作（點擊選檔） | 2.1.1 | 待驗 |

A2.7 同時是 mobile 的功能需求——觸控裝置上拖放語意無效。

## A3 — 焦點管理

| # | 項目 | 依據 | 狀態 |
|---|---|---|---|
| A3.1 | 焦點指示器可見，對比 ≥ 3:1 | 2.4.7、1.4.11 | 待驗 |
| A3.2 | 抽屜／modal 開啟時焦點移入，關閉時**回到觸發它的按鈕** | 2.4.3 | 待驗 |
| A3.3 | 檔案加入後焦點移至第一列判定列 | 2.4.3 | 待驗 |
| A3.4 | 移除判定列後焦點移至下一列；若為最後一列則回拖放區 | 2.4.3 | 待驗 |
| A3.5 | AI 建議填入時**不搶焦點** | 3.2.2 | 待驗 |

A3.5 是 Q3=A 漸進式呈現的直接後果。建議可能在使用者正在讀明細時回來（最長 5 分鐘），搶焦點會把他從閱讀中拉走。

## A4 — 不倚賴單一感官

| # | 項目 | 依據 | 狀態 |
|---|---|---|---|
| A4.1 | 無法辨識列**不只以底色標示**，金額欄必有文字「無法辨識」 | 1.4.1 | 待驗 |
| A4.2 | 雲別判定失敗**不只以 ⚠ 圖示標示**，必有文字「無法判定」 | 1.4.1 | 待驗 |
| A4.3 | 檢查通過／有問題**不只以 ✓／⚠ 或顏色區分**，徽章含文字 | 1.4.1 | 待驗 |
| A4.4 | 裝飾性圖示標記 `aria-hidden="true"` | 1.1.1 | 待驗 |

A4.1–A4.3 是同一條原則的三個落點，也是本畫面色彩使用最密集的三處。

## A5 — 對比度

| # | 項目 | 依據 | 狀態 |
|---|---|---|---|
| A5.1 | 一般文字對背景 ≥ 4.5:1 | 1.4.3 | 待驗 |
| A5.2 | 無法辨識列的 `bg-amber-50/60` 底對其文字 ≥ 4.5:1 | 1.4.3 | 待驗 |
| A5.3 | 拖放區虛線邊框對背景 ≥ 3:1 | 1.4.11 | 待驗 |
| A5.4 | 狀態徽章（green／amber）的文字對其底 ≥ 4.5:1 | 1.4.3 | 待驗 |
| A5.5 | `text-gray-400` 的圖示鈕在 hover 前對背景 ≥ 3:1 | 1.4.11 | 待驗 |

A5.5 指向既有樣式組合（`design-system-mapping.md` §2 的圖示關閉鈕用 `text-gray-400`）。`gray-400` 對白底約 2.8:1，**低於 3:1**。沿用既有組合在此處會不合格，需改為 `gray-500`。這是既有語彙與 AA 目標的第一個實質衝突。

## A11 — `ShareModal` 修補（Q7=A 的具體對象）

既有實作缺少下列**全部**六項。本區段是 `mockups.md` OQ-M1 所指的第五處 scope 漂移的實質內容。

| # | 缺口 | 修補 | 依據 | 狀態 |
|---|---|---|---|---|
| A11.1 | 無 `role="dialog"` / `aria-modal="true"` | 補於最外層 `fixed inset-0` 容器內的白卡 | 4.1.2 | 待驗 |
| A11.2 | 無 `aria-labelledby` | 指向既有 `<h2>與團隊分享` | 1.3.1 | 待驗 |
| A11.3 | 無 focus trap | Tab 在 modal 內循環 | 2.1.2 | 待驗 |
| A11.4 | 無 Escape 關閉 | `keydown` 監聽 | 2.1.2 | 待驗 |
| A11.5 | 焦點不回歸 | 關閉時回到觸發按鈕 | 2.4.3 | 待驗 |
| A11.6 | 背景未隔離 | `inert` 或 `aria-hidden` | 2.4.3 | 待驗 |

### 明確不在本站範圍內

`ShareModal` 以 `alert()` 呈現成功與失敗（第 67、71、74 行）。這既不無障礙也粗糙，但修它會改變**架構圖分享**的既有行為，超出估價表上傳的範圍。列此備忘，交由後續 intent。

這條界線值得說清楚：A11.1–A11.6 全是**加法**（補標記與行為），不改變既有互動；`alert()` 則是**改法**。前者可以安全地夾帶在本 intent 裡，後者不行。

## 驗證方式

| 層次 | 手段 | 涵蓋 |
|---|---|---|
| 自動 | `@axe-core/playwright` 掛在既有 `frontend/tests/e2e/regression.spec.ts` | A1、A5、A7.1、A10 —— 約可自動查核三成 |
| 半自動 | 鍵盤逐項走查腳本 | A2、A3、A9 |
| 人工 | 螢幕閱讀器（VoiceOver）實際操作一輪完整流程 | A4、A6、A11 |
| 人工 | 320px 與 200% 縮放的視覺查核 | A8 |

自動化只能涵蓋約三成。A4（不倚賴顏色）與 A6（播報時機）本質上無法由靜態掃描判定——axe 看得到 `aria-live` 屬性存在，看不出它在對的時機被觸發。這與 `CLAUDE.md` §3 所述的三塊結構性盲區同理：**工具全綠不等於沒問題**，這些項目必須進 TCMS 手動測案。

## Assumptions & Open Questions

**假設**

- **A-A1**：`@axe-core/playwright` 可掛進既有 e2e 設定。已確認 repo 使用 Playwright 做 e2e（`frontend/tests/e2e/regression.spec.ts`），但未驗證 axe 整合的相依衝突。
- **A-A2**：AA 是本專案首次明示的無障礙目標。既有頁面**皆未達此標準**，本清單只約束新畫面與 A11 列出的 `ShareModal` 修補，不回溯既有頁面。

**待決**

- **OQ-A1**：A5.5 發現既有的 `text-gray-400` 圖示鈕對比不足（約 2.8:1，低於 3:1）。改為 `gray-500` 會影響**所有**沿用此組合的既有元件，不只估價頁。是只在新畫面用 `gray-500`（造成兩套語彙），還是全域改（擴大影響面）？交由 functional-design。
- **OQ-A2**：A11 的六項修補歸屬 PU-13，但未計入其原始估算（`mockups.md` OQ-M1）。工作量與落點交由 delivery-planning。
- **OQ-A3**：本清單的 A 項是否要逐條進 TCMS 手動測案，或僅將無法自動化的 A4、A6、A11 進 TCMS？涉及測案數量與維護成本，交由 `tcms-test-cases` 階段。
